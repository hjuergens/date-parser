# date-rule-flex-bison

The [shared schedule example](../README.md#shared-example-schedule) in C, with a [Flex](https://github.com/westes/flex)
scanner and a [GNU Bison](https://www.gnu.org/software/bison/) parser (C skeleton, LALR(1)). Both are reentrant, so
nothing is global. It is tested against all three spec files: [schedule.txt](../examples/schedule.txt),
[catalog.txt](../examples/catalog.txt) and [date-holidays.txt](../examples/date-holidays.txt), 5960 cases.
A [Go binding](#go-via-swig), generated with [SWIG](https://www.swig.org/), runs the same cases from Go.

## Files

| File | What it does |
|---|---|
| [src/scanner.l](src/scanner.l) | Flex scanner. A word of capital letters is read as a whole and then classified (keyword, month, weekday, roll, unit letter, or a six-letter currency pair) |
| [src/parser.y](src/parser.y) | Bison grammar. The actions build the syntax tree of [ast.h](src/ast.h), left-recursive lists included |
| [src/semantics.c](src/semantics.c) | The evaluator: java.time arithmetic, business days, markets, IMM and spot dates, annual and lunar dates, equinoxes, rolling, named events |
| [src/parse.c](src/parse.c) | `schedule_parse()`: scanner and parser on one string |
| [src/schedule.h](src/schedule.h) | The public API |
| [src/lunar_tables.h](src/lunar_tables.h) | Umm al-Qura and Chinese months, generated by [scripts/lunar_tables.py](scripts/lunar_tables.py) |
| [src/main.c](src/main.c) | The command-line tool `schedule` |
| [test/run_cases.c](test/run_cases.c) | Runs the spec files; [test/spec.c](test/spec.c) reads them, with their `market` and `event` declarations and `[base market]` prefixes |
| [go/](go) | The Go package `schedule`, over the SWIG binding in [go/internal/cschedule](go/internal/cschedule/cschedule.swig) |

## Usage

```c
char error[256];
Schedule *rule = schedule_parse("T > NEXT 3RD FRI", error, sizeof error);   /* NULL on a syntax error */
Context context = { .has_base = 1, .base = date_of(2025, 6, 9) };            /* no market: Monday to Friday */
DateList dates;
if (rule && !schedule_evaluate(rule, &context, &dates, error, sizeof error)) {
    /* dates.dates[0] is 2025-06-27, in days since 1970-01-01 */
    datelist_free(&dates);
}
schedule_free(rule);
```

```
$ build/schedule -b 2025-06-09 "[T : 1W : T + 3W]"
2025-06-09
2025-06-16
2025-06-23
2025-06-30
```

## Build and test

You need a C compiler, make, Flex and Bison 3.6 or newer. The [Dockerfile](Dockerfile) has all of them, so nothing needs
to be installed on the host. From the project root:

```
docker build -t date-rule-flex-bison date-rule-flex-bison
docker run --rm -u "$(id -u):$(id -g)" -v "$PWD:/work" -w /work/date-rule-flex-bison date-rule-flex-bison sh -c 'make test && make test-go'
```

With the tools installed (`sudo apt install gcc make flex bison`), run `make test` in this folder, or `mise run test:flex-bison`.
The build runs bison with `-Werror=conflicts-sr -Werror=conflicts-rr` and compiles our own code with `-Wall -Wextra -Werror`.
`make test CFLAGS="-O1 -g -fsanitize=address,undefined"` runs the cases under AddressSanitizer (leaks included) and UBSan.

## Go via SWIG

[go/](go) is a Go module with the package `schedule`:

```go
rule, err := schedule.Parse("T > NEXT 3RD FRI")   // error: the syntax error
defer rule.Close()
base := time.Date(2025, 6, 9, 0, 0, 0, 0, time.UTC)
dates, err := rule.Evaluate(schedule.Context{Base: &base})   // [2025-06-27 00:00:00 +0000 UTC]
```

`NewMarket(rule)` and `(*Events).Add(name, rule)` take the rule over, as in C. A market caches holidays, so don't share it
between goroutines. `make test-go` builds `build/libschedule.a` and runs `go vet` and `go test`: 5960 subtests over the
spec files, as in [schedule_test.go](go/schedule_test.go), plus an ownership test and the example above. You need Go 1.24
or newer and SWIG 4; the Dockerfile has both.

- **No generated code is committed.** The `go` command runs SWIG itself on a package's `.swig` file
  (`swig -go -cgo -intgosize 64`); [cgo.go](go/internal/cschedule/cgo.go) adds the include path and links the library.
- **Error buffers.** `schedule_parse` and `schedule_evaluate` write their message into a caller's `char *error, size_t size`,
  which SWIG can't map to a Go string. The interface hides them behind helpers that take an `ErrorBuffer`, a struct whose
  `char message[256]` SWIG reads as a string. A thread-local "last error" would break, because consecutive cgo calls may
  run on different OS threads.
- **Opaque types.** SWIG gives an incomplete struct only a placeholder type (`SWIGTYPE_p_Schedule`). Declaring
  `struct Schedule {}` without a constructor or destructor (`%nodefaultctor`, `%nodefaultdtor`) gives it a Go type, while C
  still creates and frees it.
- **vet.** SWIG's wrapper turns `uintptr` into `unsafe.Pointer`, which `go vet` reports, so `make test-go` runs vet with
  `-unsafeptr=false`. `go test -race` passes.

## How the tool handles the shared example

- **Reentrant on both sides.** The scanner uses `%option reentrant bison-bridge`, the parser `%define api.pure full` with
  `%param { yyscan_t scanner }`. What they share (the arena of the tree, the error buffer) travels in `yyextra`.
- **The scanner reports its own errors.** A wrong ordinal (`2ST`) or a number that is too large returns `YYerror`, the token
  Bison 3.6 introduced for this: the parser stops without calling `yyerror`, and the scanner's message is kept.
- **Typed values.** Unlike the Java skeleton, the C skeleton types `$$` through `%union` and `%type`, so the actions need no casts.
  Small values (`Period`, `Annual`, `Date`) are kept in the union as structs; lists are linked and appended in place.
- **Name clashes.** Token names become C enumerators in `parser.h`, so a token `SEASON` and an enumerator `SEASON` of the tree
  can't both exist; the tree's kinds are named differently. The same goes for members: `Shift` already had
  a `period`, so the period of a selection (`> 3RD WED IN MONTH`) is `within`.
- **The tree is the rule.** The parser builds a tree, and [semantics.c](src/semantics.c) walks it with the context. This is the
  SableCC approach rather than closures, which C doesn't have.
- **Errors in the evaluation** unwind with `longjmp` to `schedule_evaluate`. Every list the evaluation allocates is registered
  and freed there, also after an error. A market's holidays per year are cached in the market.
- **Calendars without libraries.** The Hebrew calendar is arithmetic (after Reingold and Dershowitz, *Calendrical Calculations*).
  Umm al-Qura is observed and the Chinese calendar depends on astronomy, so both are tables generated from hijridate and lunardate,
  the libraries of the Python modules: `uv run --project ../date-rule-lark python scripts/lunar_tables.py > src/lunar_tables.h`.
  The equinoxes and solar terms are the VSOP87 code of the other modules.
