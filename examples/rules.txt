# Shared test cases for rule files: declarations that put the schedule language of schedule.txt into rules
# (rule KEY for CLASS in SCOPES [except SCOPES] [valid from/to] = <schedule> [with ...] [cites ...];, weekend, calendar).
#
# A block is a run of declarations followed by its cases; declarations after cases start a new block, evaluated on
# its own. A declaration may continue on indented lines. The cases have two forms:
#
#   <scope> <year> => <dates>          the dates of all rules for the scope in that year
#   [<base>] <schedule> => <dates>     a schedule evaluated on the calendars of the block, T = <base>
#
# <dates> is a comma-separated list of ISO dates, "none" for an empty list, or "error" (also when the block doesn't
# load: a cyclic or unknown reference, overlapping versions of a rule, a date that isn't computed). The dates of a
# scope are sorted by date, then by rule key; a date of a ONE OF alternative is followed by the alternative's name.
#
# A scope gets the rules of its own and of the scopes above it (region:AU-NSW those of country:AU) unless excluded.
# A business day or roll without ON uses the scope of the rule. Kinds closed (default) and non_working close a day,
# working_day opens one, the others (short_day, event, ...) leave it as it is.
# Rules only project: announced dates are data given to the evaluator, not part of the language, and are not tested
# here. Attributes that aren't dates (sessions, precision, citations) are checked by each implementation's own tests.
