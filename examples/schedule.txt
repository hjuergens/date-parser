# Shared test cases for the "schedule" grammar, implemented in every date-rule-* module.
#
#   <input> => <expected>
#
# <expected> is a comma-separated list of ISO dates, "none" for an empty list, or "error".
# Periods are applied left to right with java.time semantics: months (M, Q = 3M, Y = 12M)
# are added first and the day is clamped to the end of the month, then days (D, W = 7D).
# B counts business days, Monday to Friday: only Saturdays and Sundays are skipped, there are
# no holiday calendars yet. "- 1B" counts backwards, "+ 0B" leaves the date as it is.
# A range (start : step : end) yields start + k * step for k = 0, 1, ... while <= end
# (with a step of nB: start + k * n business days).
# "> IMM" moves to the next IMM date strictly after the date: the third Wednesday of
# March, June, September or December.
# "> SPOT [PAIR]" moves to the FX spot date: + 1B for USD against CAD, TRY, PHP or RUB,
# otherwise + 2B (also without pair). So 2015-12-31 > SPOT is 2016-01-04, although Jan 1 is
# a holiday.
#
# A schedule is a rule: a function of the base date and the market, both supplied when it is evaluated.
# "T" is the base date. A market only says which days are business days (B, SPOT); without one, only
# Saturdays and Sundays are skipped. The test cases name base date and market in a prefix that is not part
# of the language:  [<base>] <input> => ...  or  [<base> <market>] <input> => ...
# Markets for the tests are declared as  market <name> = <holiday>, <holiday>, ...  (plus Saturdays and Sundays).
